# Автоматическое развертывание 3x-ui / Nginx / Fail2Ban

Набор скриптов и конфигурационных файлов для автоматической подготовки Ubuntu-сервера под работу с **3x-ui**, **Nginx**, **GeoIP2**, **Fail2Ban**, **Docker** и **Certbot**.

Основная задача проекта — автоматизировать первоначальную подготовку нового сервера и привести его к состоянию, после которого остаётся вручную настроить 3x-ui и выпустить необходимые TLS-сертификаты.

## Что устанавливается

`deploy.sh` выполняет обновление системы и устанавливает необходимые компоненты:

- Nginx
- модуль Nginx GeoIP2
- Docker CE
- Docker Compose Plugin
- Fail2Ban из официального Git-репозитория
- Certbot
- Certbot Nginx Plugin
- Python 3
- pip
- setuptools
- python3-systemd
- UFW
- ipset
- Git
- curl
- unzip

> **Важно:** UFW и ipset устанавливаются как зависимости окружения, но скрипт не выполняет их ручную настройку и не создаёт правила firewall/ipset.

---

## Структура проекта

Перед запуском файлы должны находиться в одном каталоге:

```text
.
├── deploy.sh
├── install-docker.sh
├── docker-compose.yml
├── nginx-configs.zip
└── fail2ban-configs.zip
```

### `deploy.sh`

Основной скрипт автоматического развертывания.

### `install-docker.sh`

Устанавливает Docker из официального репозитория Docker:

- Docker CE
- Docker CLI
- containerd
- Docker Buildx
- Docker Compose Plugin

Если Docker и команда `docker compose` уже доступны, `deploy.sh` пропустит повторную установку Docker.

### `docker-compose.yml`

Конфигурация контейнера 3x-ui.

Рабочий каталог:

```text
/opt/docker/3x-ui
```

Данные 3x-ui сохраняются в:

```text
/opt/docker/3x-ui/db
```

Каталог Let's Encrypt подключается к контейнеру в режиме `read-only`:

```yaml
- /etc/letsencrypt:/etc/letsencrypt:ro
```

### `nginx-configs.zip`

Архив с подготовленными конфигурационными файлами Nginx:

```text
geoip2.conf
logformat.conf
vless.conf
```

Они устанавливаются в:

```text
/etc/nginx/conf.d/
```

В `vless.conf` должен присутствовать маркер:

```nginx
server_name Domain_name;
```

Во время установки `deploy.sh` запросит реальный домен и заменит `Domain_name` на введённое значение.

Например:

```text
Введите домен: cloud.example.com
```

Результат:

```nginx
server_name cloud.example.com;
```

### `fail2ban-configs.zip`

Содержит подготовленную конфигурацию Fail2Ban.

Основной конфигурационный файл:

```text
jail.local
```

устанавливается в:

```text
/etc/fail2ban/jail.local
```

Фильтры:

```text
nginx-*.conf
```

устанавливаются в:

```text
/etc/fail2ban/filter.d/
```

# Что делает deploy.sh

## 1. Обновление системы

Выполняются:

```bash
apt-get update
apt-get dist-upgrade -y
```

После этого устанавливаются необходимые системные пакеты.

---

## 2. Установка Docker

Если Docker ещё не установлен, запускается:

```bash
install-docker.sh
```

Если Docker и Docker Compose Plugin уже присутствуют в системе, этот этап пропускается.

---

## 3. Создание каталогов

Создаются необходимые рабочие директории:

```text
/opt/docker/3x-ui
/opt/docker/3x-ui/db
/opt/ammo
/etc/nginx/geo
```

---

## 4. Настройка Nginx

Перед изменением конфигурации Nginx останавливается.

Для существующих конфигурационных файлов создаются резервные копии.

В основном файле:

```text
/etc/nginx/nginx.conf
```

отключается стандартный `access_log`.

Например:

```nginx
access_log /var/log/nginx/access.log;
```

преобразуется в:

```nginx
# access_log /var/log/nginx/access.log;
```

Также добавляется:

```nginx
error_log /var/log/nginx/error.log;
```

Подготовленные конфигурационные файлы устанавливаются в:

```text
/etc/nginx/conf.d/
```

---

## 5. Настройка домена

Во время установки скрипт интерактивно запрашивает доменное имя.

Например:

```text
Введите домен: example.com
```

Значение `Domain_name` в:

```text
/etc/nginx/conf.d/vless.conf
```

заменяется на введённый домен.

Скрипт выполняет базовую проверку корректности введённого доменного имени.

Если маркер `Domain_name` отсутствует в конфигурации, развертывание останавливается.

---

## 6. Установка GeoIP

Для работы Nginx устанавливается модуль:

```text
libnginx-mod-http-geoip2
```

Базы GeoIP автоматически загружаются из проекта:

`P3TERX/GeoLite.mmdb`

Используется ссылка на последний опубликованный релиз, поэтому дата версии GeoIP не прописывается в скрипте вручную.

Загружаются:

```text
GeoLite2-Country.mmdb
GeoLite2-City.mmdb
```

и сохраняются в:

```text
/etc/nginx/geo/
```

Итоговая структура:

```text
/etc/nginx/geo/
├── GeoLite2-City.mmdb
└── GeoLite2-Country.mmdb
```

Файлы сначала скачиваются во временные `.tmp`-файлы и заменяют рабочие базы только после успешной загрузки.

---

## 7. Проверка Nginx

Перед запуском выполняется:

```bash
nginx -t
```

Если конфигурация содержит ошибку, дальнейший запуск Nginx не выполняется.

При успешной проверке Nginx включается в автозагрузку и запускается.

---

# Fail2Ban

Fail2Ban устанавливается **из официального Git-репозитория**, а не из Ubuntu APT.

Используется следующий принцип установки:

```bash
git clone https://github.com/fail2ban/fail2ban.git
cd fail2ban

python3 setup.py install
```

После установки добавляется init-скрипт:

```bash
cp files/debian-initd /etc/init.d/fail2ban
update-rc.d fail2ban defaults
```

Затем устанавливаются подготовленные конфигурационные файлы.

Перед запуском конфигурация проверяется:

```bash
fail2ban-client -t
```

Fail2Ban запускается только после успешной проверки.

---

# UFW и ipset

Пакеты:

```text
ufw
ipset
```

устанавливаются автоматически.

При этом `deploy.sh` **не выполняет**:

```bash
ufw enable
```

не открывает и не закрывает порты, не создаёт правила UFW и не создаёт собственные наборы ipset.

Дальнейшее использование этих компонентов зависит от конфигурации сервера и Fail2Ban.

---

# 3x-ui

После установки Docker файл:

```text
docker-compose.yml
```

копируется в:

```text
/opt/docker/3x-ui/docker-compose.yml
```

Контейнер запускается командой:

```bash
docker compose up -d
```

Проверить состояние можно:

```bash
cd /opt/docker/3x-ui
docker compose ps
```

или:

```bash
docker ps
```

---

# Certbot

Certbot и Nginx Plugin устанавливаются автоматически:

```text
certbot
python3-certbot-nginx
```

При этом `deploy.sh` **не выпускает TLS-сертификат автоматически**.

Сертификат необходимо получить вручную после завершения развертывания и окончательной настройки домена/Nginx.

Например:

```bash
certbot --nginx -d example.com
```

Конкретную команду необходимо выбирать в соответствии с используемой конфигурацией Nginx.

# Запуск

Склонируйте репозиторий или скопируйте все необходимые файлы на сервер.

Перейдите в каталог проекта:

```bash
cd /path/to/project
```

Разрешите выполнение скриптов:

```bash
chmod +x deploy.sh
chmod +x install-docker.sh
```

Запустите развертывание от root:

```bash
sudo ./deploy.sh
```

Во время выполнения потребуется указать доменное имя для конфигурации Nginx.

---

# Резервные копии

Перед изменением существующих конфигурационных файлов `deploy.sh` создаёт резервные копии.

Они сохраняются в:

```text
/root/deploy-backups/
```

Для каждого запуска используется отдельный каталог с временной меткой, например:

```text
/root/deploy-backups/20261001-124332/
```

Это позволяет сохранить предыдущую конфигурацию перед повторным запуском скрипта.

---

# Повторный запуск

Скрипт рассчитан на возможность повторного запуска.

В частности:

- существующие каталоги создаются через `mkdir -p`;
- существующие конфигурации сохраняются перед заменой;
- уже установленный Docker повторно не устанавливается;
- отсутствие старого конфигурационного файла не считается ошибкой;
- GeoIP загружается заново;
- Nginx проверяется перед запуском;
- Fail2Ban проверяется перед запуском.

Тем не менее перед повторным запуском на рабочем сервере рекомендуется проверить резервные копии и текущую конфигурацию.

# После завершения установки

После успешного выполнения `deploy.sh` необходимо вручную выполнить оставшуюся настройку:

1. Настроить 3x-ui.
2. Настроить необходимые inbound/fallback параметры.
3. Выпустить TLS-сертификат через Certbot.
4. Указать сертификат в необходимых компонентах.
5. При необходимости настроить firewall.
6. Проверить работу Fail2Ban.
7. Проверить доступность Nginx и 3x-ui.

Полезные команды проверки:

```bash
nginx -t
```

```bash
service nginx status
```

```bash
fail2ban-client status
```

```bash
docker ps
```

```bash
docker compose -f /opt/docker/3x-ui/docker-compose.yml ps
```

# Требования

Сценарий предназначен прежде всего для Ubuntu/Debian-подобных систем с:

- `apt`;
- systemd/SysV compatibility;
- доступом к интернету;
- правами `root`/`sudo`;
- архитектурой, поддерживаемой Docker CE и используемым образом 3x-ui.

Скрипт изменяет системную конфигурацию Nginx и Fail2Ban, поэтому рекомендуется использовать его на новом сервере либо предварительно проверить существующую конфигурацию.
